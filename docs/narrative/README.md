# 劇情文本（zh-TW）製作紀錄

文本資料在 `src/slg/narrative/data/zh_TW/`，讀取介面在 `src/slg/narrative/__init__.py`，一致性測試在 `tests/test_narrative.py`。

## 內容
| 檔案 | 內容 |
|---|---|
| `world.json` | 標題、序章、兩個劇本簡介、四季曆法、3 位君主（簡介、開場白、勝／敗結局）、9 座城池介紹 |
| `officers.json` | 42 位武將：稱號、傳略、台詞、性格標籤、關係 |
| `events.json` | 16 種事件奏報模板（各 4 個變體，佔位符 `{officer}{city}{target}{faction}{troops}`） |
| `openings.json` | **6 種「劇本×君主」開場**（`default|advantage` × 三位君主）：標題、處境、三條開局建議、語氣（優勢／均勢／劣勢） |

## 進攻局：占優的是玩家所選的君主
引擎的劇本識別碼 `advantage` 維持原義（劉備占優，舊評測、日誌、重播不變）；`advantage:faction_N` 讓第 N 家占優。
網頁新遊戲時以 `resolve_scenario(scenario, player_faction)` 轉換，因此選進攻局就是**你選的君主**兵力暴增、與其接壤的敵城兵力減半。
三種進攻局開場因此都是「優勢」，各自描述該君主的前線、後方與驕兵之險。

開場文本依實際初始資料撰寫（哪些是前線／後方城、與鄰敵的兵力強弱、各城駐守武將），
測試會對照 `build_initial_state` 檢查：必須點名該君主全部城池、不得提到別家武將、語氣須與兵力對比相符。

## 製作流程（以及為什麼這樣做）
1. 第一版由 NIM（Nemotron）直接起草，**不可用**：史實錯誤（魯肅寫成聯曹抗劉、籍貫官職多處錯）、
   寫了角色死亡、憑空捏造宿怨、事件模板寫死人名地名、混入外文字。
2. 改為：編輯整理 **人物事實卡**（`officer_fact_cards.json`，依《三國志》《演義》，只收不涉及死亡的事蹟）→
   NIM 只負責依卡片潤飾成文 → 機械檢查（字數、英文字母、死亡用語、卡外人名、佔位符、寫死名稱）不過就退回重寫。
3. 機械檢查抓不到「卡外新增的內容」，所以再做兩道審查：
   - agy（Gemini，離線 ask 模式）逐條核對史實：抓到 NIM 偷加的演義情節（拔矢啖睛）、捏造句（亮生前屢誡不改）、
     與設定矛盾句（徐庶仍在曹營），以及編輯自己的兩處錯誤（徐庶籍貫、馬超與關羽書信方向）。
     它自己也有誤報（把周瑜的「建威中郎將」、程昱的「奮武將軍」判錯），故每一條都經人工查核後才採用。
   - NIM 卡外主張稽核：再抓出數處誇飾（力能扛鼎、數十萬、窮追不捨）與一處錯誤（凌操隨孫策征黃祖）。
4. 人工編修：君主結局的地理錯置（銅雀臺不在洛陽）、暗示死亡的詞（來生）、不通順的結語。

## 已知限制
- 事實卡由編輯依記憶整理，**未逐條對照原典**；官職（稱號欄）尤其可能有誤，agy 對部分官職的質疑（于禁、張郃、凌統、韓當）無法確認，已改成較保守的稱號。需要對照《三國志》原文複核。
- 世界設定為「假想亂世」，不寫任何人物死亡；君主結局提及「登壇受禪」等情節屬架空。
- 曆法 `calendar_label` 假設一回合＝一季（僅供顯示，引擎未規定回合長度）。
- 網頁介面已接入：`GET /api/narrative?scenario=&faction=`（開局前即可呼叫）、設定畫面的劇本預覽、開局簡報彈窗、城池介紹、武將傳略、回合徽章的年季。
  事件奏報模板（`events.json`）尚未套用到結算畫面——引擎事件目前是字串，需要先改成結構化事件。
- 曆法：玩家第一個回合（turn=1）是「第1年春」，四回合一年（僅供顯示）。

## 事件文字已接入畫面（2026-10-22）
`web/payload.py::story_lines` 把上一回合玩家看得到的**攻城勝敗、守城成功／失守、武將出奔**，用 `events.json` 的模板轉成敘事句，放在 `/api/status` 的 `story` 欄位，前端（`panels.js` 戰報區）顯示在原有事件清單之上。開發、徵兵、移動等例行事件仍只列原文，不另外敘事。為了判斷「誰是守方」，`ResolutionEvent` 新增選填欄位 `defender_faction`（不影響既有行為與重播）。尚未接入：忠誠警告／稱讚、饑荒、滅國模板（引擎目前沒有對應事件）。
