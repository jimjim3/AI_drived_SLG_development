# 完整戰略遊戲路線圖

狀態:2026-11-14 起草,取代 README「下一步」與 HANDOFF「待辦」作為主規劃。各里程碑的時程是粗估,以「一人加 AI 協作」的開發量估算。標「待決」的項目需要專案負責人決定。

---

## 0. 一句話定位

> **一款三國策略遊戲:每位君主、太守、武將都由 AI 扮演,各有自己的意志;玩家可以坐上任何一層的位置,與 AI 遵守完全相同的規則。**

和光榮《三國志》系列的差別不在地圖或數值,而在三件事:
1. **人物會自己做決定。** 太守會曲解或違抗命令,武將會因冷落出奔,盟友會算計背盟。故事是從決策中長出來的,不是寫死的事件。
2. **玩家可以扮演任一層。** 當君主統一天下;當太守,在 AI 主公底下發展地方;或當一名武將,選擇效忠或另投明主。三種玩法都用同一個引擎、同一套介面。
3. **對稱與公平。** 玩家看到的畫面就是 AI 收到的輸入。沒有 AI 作弊,也沒有玩家全知。

### 0.1 設計支柱(所有新功能都要對照)

| 支柱 | 含義 | 檢驗問題 |
|---|---|---|
| 引擎是唯一真理 | AI 只從合法行動中選,引擎再驗證 | 這個功能能用 `legal_actions` 加 `validation` 表達嗎? |
| 對稱 | 玩家與 AI 同一介面、同一視野 | 規則 AI、LLM、人類都能操作它嗎? |
| 人物有意志 | 決策受能力、性格、忠誠、關係影響 | 它會產生「某人做了某個選擇」的故事嗎? |
| 可重播 | 固定種子加決策日誌,可 100% 還原 | 它是否只依賴種子亂數與記錄下的決策? |
| 能離線玩 | 沒有 LLM 時規則 AI 也能完整跑完一局 | LLM 斷線時遊戲還能進行嗎? |
| 史實為底、允許 IF | 劇本貼近史實,走向開放 | 它能讓歷史「走歪」嗎? |

### 0.2 目標體驗
- **玩家**:玩過光榮三國志 II~XI、喜歡 Crusader Kings 那種人物劇情的人;另外是對 AI 代理有興趣的人。
- **一局長度**:小劇本 1 小時,大劇本 3~6 小時(可存檔)。
- **平台**:網頁優先,桌機與平板都能玩。Godot 只在需要大量動畫時才當純展示端(依據 `docs/memos/2026-10-13-godot-feasibility.md`)。

## 1. 核心循環

```
劇本選擇 → 開場簡報
  └─ 每回合(一季)
       1. 情報:勢力摘要、前線、事件、上回合戰報、史書
       2. 君主:戰略意圖(各城角色、主攻目標、外交)
       3. 太守:在意圖與裁量權內分派城內武將
       4. 武將:執行;遇到需要判斷的事件才個別決策(出使、受勸降、戰場、抗旨)
       5. 結算:內政 → 移動與行軍 → 戰鬥 → 外交 → 人事(忠誠、出奔、登用、壽命) → 事件
       6. 史書:本回合大事的敘事
  └─ 勝利或失敗:統一、劇本目標、年限評分;滅亡後可「轉生」為在野武將繼續
史書回顧 → 解鎖 IF 劇本或成就
```

**時間單位**:目前一回合 = 一季。**待決**:大地圖劇本是否改成一回合 = 一個月(三國志 IX 式)。建議維持一季,搭配多回合行軍,控制 LLM 呼叫量。

## 2. 遊戲系統藍圖

每個系統列出:**現況** → **目標** → 分在哪個里程碑(M1~M4,見第 6 節)。

### 2.1 地圖與地理
- **現況**:9 城節點圖;距離折損(§20);資料庫已有 105 城與 228 條邊,未接入、未核實。
- **目標**:
  - M1:劇本級地圖(約 20 城)。城池分大中小,有關隘節點(虎牢關、潼關、劍閣)。
  - M2:地形屬性(平原、山地、水域);邊有類型(道路、山道、水路),影響行軍天數、兵種效率、補給。
  - M3:全圖 105 城,分州。州是「刺史、州牧」官職與統治加成的單位。
  - M3:水路與水軍(赤壁、長江防線)。孫權的地理優勢應該來自水軍,而不是單純的地圖位置。

### 2.2 內政與經濟
- **現況**:金、糧、農業、商業、城防、兵;收入有擾動;糧荒會逃兵。
- **目標**:
  - M1:**人口**(兵源上限與稅基)、**民心**(影響收入、徵兵、叛亂)。徵兵要扣人口與民心。
  - M1:季節:秋收入糧,春季發金;冬季行軍糧耗加倍。
  - M2:**治安與叛亂**:民心過低出現黃巾、山賊,成為中立勢力。
  - M2:**災害**:蝗災、疫病、水災。隨機,但受治水、農業影響。
  - M2:**特產與交易**:涼州馬、蜀錦、鹽鐵;城間運輸、商人買賣糧。
  - M3:**官職與俸祿**:武將有官位,俸祿是固定支出;封官能提升忠誠。
  - M3:**建設**:城內建築(市場、兵營、屯田、烽火台),取代單純的數值開發。

### 2.3 軍事
- **現況**:攻城一次結算;出兵只能從單一城池;有勝算估計與規則判定;多套戰鬥規則可切換。
- **目標**:
  - M1:**部隊實體**:出征成為地圖上的部隊,帶兵、帶糧、有主將與副將,行軍多回合,可被攔截。
  - M1:**野戰**:兩支部隊相遇,或攔截援軍時結算。目前只有攻城。
  - M1:**援軍**:鄰城部隊可馳援被圍城池。
  - M2:**兵種**:槍、戟、弓、騎、水軍,有相剋;城池依特產決定能徵什麼兵。
  - M2:**士氣與訓練**:新兵士氣低;連勝提升士氣;斷糧大降。
  - M2:**計略**:火計、離間、偽報、埋伏,由智力武將執行,成功率由引擎計算。
  - M2:**俘虜處置**:登用、釋放、斬首、交換。斬首影響全國武將的忠誠與名聲。
  - M3:**戰鬥演出**:回合制戰術小地圖(選配)。**待決**:是否需要。建議只做「自動結算 + 戰報敘事 + 單挑事件」,不做戰術地圖,控制工作量。
  - M3:**單挑**:武力型武將的事件決策,由武將本人(AI 或玩家)選擇應戰或迴避。

### 2.4 人物
- **現況**:42 名武將;統、武、智、政與忠誠;冷落與出奔機制(長局才觸發);肖像 48 張。
- **目標**:
  - M1:**性格向量**:野心、義理、勇猛、謹慎、貪財。決定規則 AI 的傾向,也寫進 LLM 提示。
  - M1:**在野武將與登用**:城中可搜尋在野人才;招攬成功率看魅力、名聲、相性。
  - M1:**功績與升遷**:立功累積功績 → 升官 → 可任太守。
  - M2:**關係網**:血緣、結義、師徒、夫妻、仇敵。親屬可作人質;仇人同城會內鬨。
  - M2:**登場與壽命**:依生卒年登場、病故;子嗣繼承。
  - M2:**特技**:神算、火計、騎兵、水軍、屯田等,約 20 種,影響行動效果。
  - M3:**人物記憶**:每位重要武將保留簡短記憶摘要(被冷落、被救過命、主公殺過他的兄弟),供 LLM 決策時引用。
  - M3:**名聲**:勢力與個人名聲,影響登用、外交、民心。

### 2.5 外交
- **現況**:同盟第一、二階段已做(友好度、提議與接受、背盟懲罰、金錢抵押、共享視野、網頁外交分頁)。結論:懲罰改變不了背盟率(EVALUATION §22)。
- **目標**:
  - M1:**停戰**(N 回合不得互攻,比同盟輕)、**勸降**(對殘弱勢力)。
  - M2:**人質與聯姻**:用人物系統的親屬。人質的存在讓背盟有「人」的代價,背盟問題可能在這裡才有解。
  - M2:**共同作戰**:同盟可約定共攻某城,失約扣友好度。
  - M2:**第三方反應**:背盟者名聲下降,所有勢力對他的接受門檻上升。這是金錢懲罰以外的槓桿。
  - M3:**朝廷與天子**:擁天子的勢力可以下詔(討伐令、官職冊封),其他勢力的應詔與否影響名聲。
  - M3:**外交使者為武將行動**:由武將出使,用他的智力、政治、魅力影響結果;LLM 武將可在出使時談判條件。

### 2.6 情報
- **現況**:戰爭迷霧(己城與相鄰前線可見);同盟共享視野。
- **目標**:
  - M2:**斥候與細作**:派武將偵察遠方城池;情報有誤差,依智力而定。
  - M2:**情報過期**:看過的城顯示「N 回合前的數字」。
  - M3:**謠言與偽報**:敵方計略可讓你看到假情報。太守也可能謊報(DESIGN.md 原構想)。

### 2.7 事件與劇情
- **現況**:劇情文本(42 武將事實卡、事件模板、開場);戰報敘事句;29 個劇本草稿(未核實)。
- **目標**:
  - M1:**史實事件引擎**:條件觸發(年份、人物在場、城池歸屬),例如三顧茅廬、桃園結義。條件不滿足就不發生,也就是 IF。
  - M2:**隨機事件**:豐收、瘟疫、名士來訪、叛亂。
  - M2:**史書**:每回合結算後,由 LLM 或模板寫一段史書,局末彙整成一部「本局三國志」,可匯出。
  - M3:**IF 劇本**:「呂布未死」「關羽守住荊州」這類分歧開局。

### 2.8 勝利條件與難度
- **目前**:回合結束時城最多者勝。
- **M1**:統一(占領全部或八成以上城池)、劇本目標(例如官渡劇本:曹操擊敗袁紹)、年限評分(城、人口、名聲、武將)。
- **M2**:難度分級:AI 模型等級、初始資源、AI 個性;另外有「史實模式」,AI 傾向照史實行動。
- **M3**:成就與排行(本機)。

## 3. AI 架構(本專案的核心賣點)

### 3.1 三層決策

| 層 | 呼叫頻率 | 看到什麼 | 輸出 | 現況 |
|---|---|---|---|---|
| 君主 | 每勢力每回合 1 次 | 勢力摘要、外交、已知敵情、史書 | 結構化意圖:各城角色、主攻目標、外交動作、`latitude` | 部分(目前直接下到武將的命令) |
| 太守 | 每城每回合 1 次(只在有選擇的城) | 本城詳情、君主意圖、城內名冊 | 城內武將分派 | **未做** |
| 武將 | 事件驅動 | 自身、任務、性格、記憶 | 出使談判、應對勸降、單挑、抗旨 | **未做** |

- **意圖下傳**:用結構化 JSON 加一句說明;`latitude` 決定太守能偏離多少(DESIGN.md §1)。
- **抗旨**:太守的偏離 = f(忠誠、性格、意圖與本城利益的衝突)。由引擎擲骰決定「是否有偏離的機會」,再由 AI 選怎麼偏離。玩家當君主時會遇到被違抗;當太守時可以自己選擇違抗。
- **委任**:玩家可以把任何一層交給 AI,例如自己當君主、太守全交 AI;也可以全部親自下令(現況)。

### 3.2 AI 等級與成本控制

| 等級 | 君主 | 太守 | 武將 | 每回合呼叫(3 勢力、20 城) | 用途 |
|---|---|---|---|---|---|
| L0 規則 | 規則 | 規則 | 規則 | 0 | 離線、測試、平衡大量模擬 |
| L1 君主 LLM | LLM | 規則 | 規則 | 約 3 | **現況**;低延遲 |
| L2 分層 | LLM | LLM(有選擇時) | 規則 | 約 3 + 6~15 | 標準體驗 |
| L3 全人格 | LLM | LLM | 事件時 LLM | 再加 0~5 | 劇情最豐富 |

延遲與成本對策:
- **平行呼叫**:各勢力、各太守彼此獨立,同時送出。
- **跳過**:沒有實質選擇的城(只能休養)不問 AI。
- **批次**:一次呼叫處理同州多城。
- **預算**:每回合 token 上限;超過就降級到規則 AI。
- **背景運算**:玩家思考時,AI 勢力先做決定(AI 看不到玩家當回合的決定,不影響公平)。
- **小模型處理小事**:武將事件用小模型,君主用大模型。

### 3.3 模型策略
- **免費**:NVIDIA NIM(Nemotron)、本機或 Colab Qwen;離線用 `DemoCompleter` 加規則 AI。
- **付費選項**:OpenAI 相容端點都能接(Gemini、Claude 等)。玩家自備金鑰。
- **待決**:是否提供「伺服器代付」的線上版本。這涉及成本與濫用防護,建議 M4 以後再談。

### 3.4 AI 品質指標
每次改提示或規則都用基準測試量:
- **合法率**:被拒指令占比。
- **意圖遵從率**:太守行動符合君主意圖的比例。
- **戰略品質**:對規則 AI 的勝率、兵力與城池曲線、勝算低於 1 卻出兵的比例。
- **人格一致性**:同一武將在相似情境下的選擇是否符合性格(抽樣人工標註)。
- **成本**:token、秒數、每局花費。

## 5. 內容

### 5.1 劇本
- **現況**:引擎內 3 個劇本變體(default、advantage 等);資料庫 29 個時期草稿(184 黃巾 ~ 280 晉滅吳),**全部未核實**,Nemotron 交叉審稿意見很雜。
- **核實流程**(每個劇本):
  1. 列出勢力、城池歸屬、武將所在。
  2. 兩個模型交叉審稿(已有工具)。
  3. 人工對照《三國志》、《資治通鑑》。
  4. 自我對弈 20 局,檢查開局平衡與史實傾向。
  5. 標 `verified`。
- **首發順序**:
  - M1:**200 官渡**。勢力數適中(曹、袁、劉、孫、劉表、劉璋等),戲劇性強。
  - M2:**190 反董卓**、**208 赤壁**。
  - M3:再加 6~10 個,包含 184 黃巾、219 荊州、234 五丈原。
  - M4:全部 29 個,加上 IF 劇本。

### 5.2 武將資料
- **能力值版權**:光榮的武將數值表是灰色地帶(PRIOR_ART.md §D)。`data/sanguo/koei_stats.json` 只能作開發參考,**發布版必須用自訂數值**:由事蹟、史傳推導,LLM 輔助、人工抽查,並記錄出處。M2 前完成。
- **人數**:M1 約 120 人(官渡劇本)→ M2 約 300 人 → M3 約 600 人。
- **肖像**:現有 Qwen-Image 管線(Colab ComfyUI)。風格要統一,先產生主要人物,次要人物用通用肖像。

### 5.3 文本
敘事模板、史書、事件文本以繁體中文為主;**待決**:是否要簡體中文、英文、日文。模板化文本可以由 LLM 翻譯後人工抽查。

## 6. 里程碑

### M0 收斂(1~2 週)
目標:把現有東西變成能拿給別人玩的狀態,並取得第一批真人資料。
- 瀏覽器端到端測試加截圖(`scripts/e2e_web.py`)。
- **存檔與讀檔**,伺服器持久化。
- 真人試玩 3 局:你 1 局、另找 2 人;用 cloudflared 遠端。記錄無聊、卡住、看不懂的地方。
- 更新 README、HANDOFF;本文件取代舊待辦。
- 凍結數值調整(同盟、戰鬥)。

**完成標準**:3 份試玩紀錄、存檔可用、文件反映現況。

### M1 垂直切片「官渡之戰」(6~8 週)
目標:**一個劇本做到「好玩、可玩完」**,證明核心體驗。
- 引擎:20 城左右的劇本格式與載入器;人口與民心;季節;部隊實體、多回合行軍、野戰、援軍;勝利條件。
- 人物:性格向量、在野登用、功績升遷,約 120 人(官渡劇本已核實)。
- 外交:同盟(已有)、停戰、勸降。
- **AI:太守層(L2)**、意圖與 `latitude`、基本抗旨。
- 事件:史實事件引擎,至少 8 個官渡相關事件。
- 介面:可縮放地圖、部隊圖示、兩層軍令介面、AI 思考進度。
- 評測:L0、L1、L2 三組各 20 局(兩個模型);意圖遵從率。

**完成標準**:試玩者能在 1~2 小時內玩完一局,至少一半的人說想再玩;L2 對 L1 有可量測的差異(勝率或故事性擇一)。

### M2 Alpha(2~3 個月)
- 劇本:加上 190 反董卓、208 赤壁(共 3 個)。
- 系統:兵種、士氣、計略、俘虜處置、特技、關係網、壽命與登場、治安與叛亂、災害、特產;情報系統。
- 外交:人質與聯姻、共同作戰、第三方反應(名聲)。
- 玩家可扮演**太守**。
- 史書生成與匯出;新手引導;難度設定。
- 自訂能力值,完全取代光榮數值。
- 公開 Alpha:遠端試玩 10 人以上,問卷回饋。

### M3 Beta(3~4 個月)
- 全地圖 105 城、分州、水路與水軍;10 個以上劇本。
- 人物記憶、名聲、官職、建設。
- 朝廷與天子;外交使者為武將行動。
- 玩家可扮演**武將**;滅亡後轉生。
- 戰鬥演出、單挑。
- 效能:105 城的規則 AI 每回合 < 1 秒;LLM 回合 < 30 秒(平行加背景運算)。
- 大規模平衡:每劇本 100 局 L0 加 20 局 L2。

### M4 1.0 發布
- 29 個劇本加 IF 劇本;模組支援(劇本與武將 JSON 格式公開、驗證工具)。
- 打包:網頁公開版(玩家自備 API 金鑰或用規則 AI)、桌面版(選配)。**待決**:發布管道(GitHub Pages 加自架伺服器、itch.io、Steam)。
- 版權清查:素材、數值、文本出處。
- 開發誌或教科書改寫為「怎麼做出這個遊戲」。

### M5 之後(候選)
線上多人(每位玩家一個勢力,AI 補位)、語音旁白、Godot 展示端、演義模式(誇張的單挑與計略)、與學術合作的 AI 行為研究資料集。

## 8. 平衡與評測方法

- **自我對弈是平衡工具**:每個劇本固定一組基準(L0 100 局、L2 20 局 × 2 個模型)。
- **指標**:
  - 每勢力勝率與名次分佈。
  - 滾雪球程度:第 N 回合領先者最後勝出的比例。
  - 一局長度、滅國時間。
  - 戰鬥次數、被拒指令比例。
  - 「無聊回合」比例:玩家勢力沒有任何有意義選擇的回合。
- **統計**:回報 95% 信賴區間;每格少於 20 局的結果只當方向參考(此前 §11~§22 多數屬於這類)。
- **人工評測**:每個里程碑都有試玩問卷(好玩、清楚、想再玩、哪裡卡住)。

## 9. 風險與對策

| 風險 | 影響 | 對策 |
|---|---|---|
| 範圍太大(一人專案) | 永遠做不完 | 垂直切片優先;每個里程碑都要可玩;本文件每月檢討刪減 |
| LLM 延遲 | 等太久就不好玩 | 平行、背景運算、跳過無選擇的城、AI 等級可調 |
| 免費 API 不穩(NIM 曾 404、503) | 對局卡住 | 多後端備援;規則 AI 兜底(已有) |
| LLM 行為無法重現 | 除錯困難 | 日誌記錄決策,以重播重現(已有) |
| 史實資料錯誤 | 玩家信任下降 | 核實流程;未核實的劇本標「實驗」 |
| 版權 | 無法公開發布 | 自訂數值;自產美術;史實人名不受保護 |
| 平衡不佳(東南角優勢等) | 某些勢力無聊 | 劇本目標差異化;大量自我對弈 |
| AI 太笨或太會背叛 | 體驗差 | 性格、名聲、人質等槓桿;難度分級 |
