# 第 1 章：動機：為什麼讓 LLM 當君主

## 本章學習目標

1. 理解傳統全 LLM 代理架構在大型策略遊戲中面臨的 Token 爆炸困境，並掌握量化估算方法。
2. 分析既有研究（如 CivAgent、CivRealm、vox-deorum）在遊戲 AI 領域的得失與邊界，識別分層決策的必要性。
3. 闡述「勢力敘事」與分層決策架構的核心邏輯，包括君主、太守與武將的職責切分及資訊流設計。
4. 釐清遊戲機制與文學作品的法律邊界，理解著作權不保護機制與公有領域素材在獨立研發中的關鍵作用。
5. 熟悉本全書的章節結構與技術路線，從世界規則、注意力經濟到安全網與實證數據的邏輯脈絡。

## 1.1 全 LLM 代理的虛妄

在大型多人線上策略遊戲或複雜的回合制模擬中，最直覺的實現方式是讓大語言模型（LLM）直接控制每一個遊戲單位。然而，這種「全 LLM 代理」架構在工程與經濟層面均面臨嚴峻挑戰。以本專案設定的規模為例，若採用「每位武將每回合都問」的策略，在 400 人規模的戰場上，每回合將產生約 420 次 API 呼叫。假設每次呼叫的平均輸入與輸出 Token 數為 1,500，則單回合的 Token 消耗量高達 ~630k。

這一數字在長週期的遊戲對局中將呈指數級增長。一局標準的 300 回合對局，若維持上述呼叫頻率，總耗費將超過 1.9 億 tokens。不僅 API 調用成本將變得無法承受，單次請求的延遲（Latency）也會嚴重影響遊戲的流暢度與即時性。在同步對戰或多勢力並行決策的場景下，等待所有 LLM 回應的時間將成為系統瓶頸，導致遊戲體驗極度割裂。此外，LLM 的輸出具有隨機性，若缺乏嚴格的結構化約束，400 個獨立代理可能產生大量非法或相互衝突的指令，進一步增加引擎處理與驗證的負擔。

因此，單純依賴 LLM 進行微觀決策不僅在成本上不可行，在系統穩定性上也存在巨大風險。必須尋找一種既能保留 LLM 高層戰略智慧，又能大幅降低計算開銷的架構。這正是本專案提出「分層決策」與「勢力敘事」模式的根本動機：將決策權上收，讓 LLM 專注於宏觀戰略與關鍵事件，而將重複性、機械性的微觀操作交由確定性的規則引擎或輕量級代理處理。

## 1.2 相關研究借鏡

在探索分層決策架構之前，有必要回顧既有研究在遊戲 AI 領域的嘗試與發現。CivAgent 專案基於開源遊戲 Unciv，展示了 LLM 在自然語言外交與基本策略執行上的潛力，但其架構仍偏向讓 LLM 直接參與較多層級的決策。CivRealm 則在 Freeciv 環境中探討了強化學習（RL）與 LLM 代理的結合，其結論指出 LLM 在完整遊戲流程中仍顯吃力，特別是在長期規劃與資源精確管理上，這提醒我們必須依靠分層結構與規則 AI 進行補位。

更具啟發性的是 vox-deorum 專案，該專案在《文明 V》中實踐了「LLM 只負責宏觀戰略，微操交給原本的演算法 AI」的分層理念。其實證結果顯示，這種架構不僅能跑完 400 回合的長對局，且勝率與原生 AI 持平。這幾乎就是本專案「分層」理念的預演與實證。vox-deorum 的成功在於它明確界定了 LLM 的邊界：LLM 不負責具體的單位移動或生產指令，而是制定高層目標，由底層演算法執行。

## 1.3 勢力敘事與層級切分

為了解決 Token 爆炸問題，本專案提出了「勢力敘事」（Faction Narrative）模式，將全勢力的決策壓縮為每回合單次 LLM 呼叫。在這一模式下，LLM 扮演「史官」或「君主」的角色，以敘事的方式輸出該回合的戰略重點與關鍵指令。具體而言，LLM 的輸出包含三個部分：`orders`（關鍵武將的具體指令）、`chronicle`（本回合的敘事描述）與 `next_cast`（下回合需重點關注的武將名單）。

這種層級切分遵循了傳統策略遊戲的指揮鏈邏輯：君主決定戰略方向（如主攻目標、外交姿態），中層（太守）執行配置（如城內資源分配），基層（武將）則由事件驅動（如戰場戰術、被策反時的反應）。在「勢力敘事」模式中，LLM 僅需關注被點名的關鍵武將（通常為 5～8 人），而未點名的武將則由引擎自動委任規則 AI 處理。這種設計將每回合的 LLM 輸入量從隨勢力規模線性增長，轉化為幾乎恆定的小規模輸入。

例如，即使一個勢力擁有 200 位武將，LLM 的輸入也僅包含勢力摘要、出場名單（上限 6 人）與引擎強制插入的事件武將。其餘武將僅以名字列於名冊中，供 LLM 在必要時點名。這種「聚光燈」機制不僅大幅降低了 Token 成本，還引入了「注意力經濟」的遊戲機制：武將若長期未被點名，可能觸發忠誠下降或出奔事件，從而將技術限制轉化為遊戲玩法。

## 1.4 智慧財產與公開領域邊界

在進行獨立研發時，釐清法律邊界是確保專案可持續發展的基石。首先，遊戲的規則與機制本身不受著作權保護。根據著作權法中的 idea/expression 二分法，遊戲的玩法、機制、數值平衡等屬於「思想」或「機制」層面，而非受保護的「表達」。因此，開發類似《三國志》的策略遊戲機制，只要不直接複製原作的程式碼、圖像、音樂或文字劇本，即不構成侵權。

其次，本專案所依據的歷史素材主要來自《三國演義》原文與陳壽《三國志》。這些作品均已進入公有領域（Public Domain），其人物、事件與基本敘事可自由使用。這為獨立研發提供了合法的內容基礎，允許開發者自由地重新詮釋歷史與創建新的遊戲情境。需要注意的是，現代遊戲（如 KOEI 系列）的特定武將數值表、美術資產與程式碼仍受著作權保護，因此本專案採用自行設計數值與程式生成頭像的方式，避免使用任何受保護的素材。

## 1.5 本書結構與章節地圖

本全書旨在系統性地闡述分層 AI 決策策略遊戲的設計、實作與實驗。第 2 章將詳細介紹遊戲世界與規則，包括地圖拓撲、資源系統與戰鬥機制。第 3 章探討設計原則，重點在於引擎作為唯一真理來源與 AI 作為可替換插件的架構理念。第 4 章深入剖析「勢力敘事」與注意力經濟，解釋如何將 Token 限制轉化為遊戲機制。

第 5 章聚焦於引擎實作與安全網，詳細說明如何確保 AI 決策的合法性與系統的穩定性。第 6 章介紹 LLM 代理的具體實作，包括結構化輸出解析與多後端支援。第 7 章探討忠誠、冷落、抗旨與出奔等動態機制，這些機制賦予了遊戲角色更深層的情緒與行為邏輯。第 8 章至第 10 章則呈現評測方法與兩組關鍵實驗：第 9 章分析 Gemini 的三個階段表現，第 10 章則展示本機 Qwen 大規模實驗的結果。

最後，第 11 章總結開發方法論，強調分層外包與驗收的重要性；第 12 章誠實記錄已知缺陷與開放問題；第 13 章則展望下一步與實驗路線圖。附錄部分提供了術語表、指令速查與檔案地圖，方便讀者快速查閱。透過這一嚴謹的結構，本書希望為讀者提供一個從理論到實作、從設計到驗證的完整視角。

## 本章重點

1. 全 LLM 代理架構在 400 人規模下每回合消耗 ~630k tokens，300 回合對局成本高達 1.9 億 tokens，延遲與成本均無法承受。
2. 既有研究如 vox-deorum 證實了分層決策（LLM 宏觀、演算法微觀）的有效性與可行性，為本專案提供了重要借鏡。
3. 「勢力敘事」模式通過將全勢力決策壓縮為每回合單次 LLM 呼叫，並結合出場名單與事件驅動機制，將 Token 成本降低至 ~30k-60k 水平。
4. 遊戲機制不受著作權保護，而《三國演義》與《三國志》屬於公有領域，為獨立研發提供了合法且豐富的內容基礎。
5. 本全書從世界規則、設計原則、引擎實作到實驗驗證，系統性地呈現了分層 AI 決策策略遊戲的完整開發與評估過程。

## 習題

1. 假設一個勢力擁有 100 位武將，若採用「每位武將每回合都問」的策略，每次呼叫平均 1,500 tokens，請計算該勢力單回合的 Token 消耗量，並與「勢力敘事」模式（假設每次呼叫 3,000 tokens）進行比較。
2. 在「勢力敘事」模式中，為什麼需要引入「出場名單」（next_cast）機制？如果取消此機制，直接讓 LLM 關注所有武將，會對 Token 成本與 LLM 的決策品質產生什麼影響？
3. 根據著作權法的 idea/expression 二分法，解釋為什麼開發一款機制類似《三國志》的遊戲不構成侵權，但直接複製 KOEI 的武將數值表或美術資產卻可能構成侵權。
4. 在分層決策架構中，「太守」層的主要職責是什麼？為什麼將「太守」層設計為批次單位（一次呼叫決定整座城多位武將的工作）比讓每位武將獨立呼叫更具成本效益？
5. 本專案提到「把限制變成玩法：受冷落」。請解釋這一機制是如何將技術上的注意力上限（Token 限制）轉化為遊戲機制，並分析其對玩家體驗與遊戲策略深度的潛在影響。
