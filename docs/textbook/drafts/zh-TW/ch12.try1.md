# 第 12 章：已知缺陷與開放問題

## 本章學習目標
- 理解 LLM 代理在策略遊戲中出現「決策惰性」的結構性原因，並分析 `rest` 行動高比例背後的誘因設計缺失。
- 辨識地緣結構對勢力平衡的影響，特別是東南席位（`faction_3`）的邊角優勢如何導致自我對弈失衡。
- 剖析規則定義中的邏輯封閉性缺陷，說明為何深處後方的武將（如宛城、漢中）在當前機制下完全無法觸發叛逃。
- 評估評測流水線（Evaluation Pipeline）在長局模擬中的可觀測性限制，理解「整組結束才寫檔」對即時診斷造成的盲點。
- 分析資源爭用與決策反饋粗糙性對 LLM 決策品質的影響，特別是同城金幣爭用導致的高拒絕率與攻城歸因提示的不足。

## 12.1 決策惰性與消極休整

在當前系統實作與實驗結果中，最為顯著且亟待解決的行為異常之一，是 LLM 代理在決策過程中展現出極高的「決策惰性」（Decision Inertia），具體表現為大量選擇 `rest`（休整）行動。根據實驗數據統計，`rest` 行動在總決策中的比例高達約 47%。這一數據遠高於預期，反映出深層戰略誘因設計之不足。

從遊戲理論的角度來看，一個理性的策略代理應在確保生存的前提下，積極追求資源累積、領土擴張或軍事優勢。然而，當 LLM 面臨複雜的狀態空間與不確定的結果時，若系統未能提供足夠強烈的正向激勵或清晰的風險回報比，模型往往傾向於選擇最安全、成本最低的行動。在目前的遊戲引擎中，`rest` 行動通常意味著保持現狀、不消耗額外資源且不會引發負面後果。這種「無痛」特性使得 LLM 在缺乏明確進攻信號或防禦壓力時，將 `rest` 作為預設的「安全港」。

此現象揭示了當前提示詞工程（Prompt Engineering）與視圖設計（View Design）之間的斷層。雖然視圖提供了城池兵力、資源與敵情情報，但 LLM 難以從中推導出「立即行動」的緊迫感。例如，當敵方兵力略低於我方時，規則 AI 可能會選擇進攻以擴大優勢，但 LLM 可能因無法精確計算攻城勝率或擔心兵力損耗，而選擇 `rest` 以維持現狀。這種消極休整不僅浪費了回合資源，更導致遊戲節奏緩慢，使得長局模擬中出現大量無意義的拉鋸戰。

此外，47% 的 `rest` 比例也暗示了 LLM 對「機會成本」的感知不足。在策略遊戲中，時間本身就是資源，每一回合的猶豫都意味著潛在戰略機遇的流失。未來的改進方向應包括：在視圖中引入更顯式的「威脅指數」或「機會窗口」指標，並在系統提示詞中明確強調「主動性」的重要性，引導 LLM 在風險可控時採取積極行動，而非一味休整。

## 12.2 地緣結構與座位優勢

三國策略遊戲的核心魅力在於其地緣政治結構，但目前的劇本設計與初始條件設定導致了嚴重的座位不平衡（Seat Imbalance）。在 Q4 自我對弈實驗中，東南席位的孫權勢力（`faction_3`）在 4 局對局中全部勝出，顯示出極端的邊角優勢。這種不平衡並非偶然，而是由地圖結構與初始資源分配共同作用的結果。

`faction_3` 位於地圖東南角，其地緣特徵為「背靠邊界、面向中心」。這種位置使其只需防守一條主要邊界線，而無需應對多線壓力。相比之下，位於中心的曹操勢力（`faction_1`）或劉備勢力（`faction_2`）則面臨多方向敵人的威脅。在自我對弈中，由於所有代理均為同一模型，策略水平相當，地緣優勢便成為決定勝負的關鍵因素。`faction_3` 可以利用其邊角位置進行穩定的經濟發展，並在敵方疲於多線作戰時，集中兵力進行單邊突破。

這種座位優勢導致了自我對弈的失衡，使得實驗結果難以反映 LLM 策略能力的真實差異。在 Q1 與 Q3 實驗中，`faction_3` 的兵力領先也印證了這一點。若不對此進行平衡，任何基於當前劇本的評測結果都將受到地緣因素的嚴重干擾，無法準確衡量 LLM 在純粹策略層面的表現。

此外，曹操勢力的多線受敵特性也增加了其決策的複雜度。規則 AI 可以通過預設的優先級規則快速應對多線威脅，但 LLM 需要同時評估多個方向的風險與回報，這極大增加了其認知負荷。在當前實作中，LLM 往往無法有效分配注意力，導致在多線作戰中表現不佳。這不僅是地緣設計的缺陷，也反映了 LLM 在處理高維度狀態空間時的局限性。

未來的改進應包括重新設計地圖或初始條件，以減少座位間的結構性差異。例如，可以調整邊角勢力的初始資源或增加其邊界壓力，以平衡其地緣優勢。同時，在評測中應採用多座位對照實驗，以分離地緣因素與策略能力的影響。

## 12.3 叛逃封閉性缺陷

忠誠與叛逃機制是模擬三國人物關係的重要組成部分，但目前的實作存在嚴重的邏輯封閉性缺陷。具體而言，位於宛城與漢中的武將，由於深處後方且不與任何敵城相鄰，在規則定義下完全無法出奔（Defect）。這一缺陷使得忠誠機制在這些區域的武將身上完全失效，導致模擬結果與歷史或預期行為產生偏差。

根據遊戲規則，武將出奔的前提條件之一是「與敵城相鄰」或「處於前線」。這一設計旨在模擬武將在前線受挫或目睹敵強我弱時選擇投降的歷史現象。然而，對於深處後方的武將，如宛城與漢中的守將，由於其城池不與敵城直接相鄰，系統判定其不具備出奔的條件。這意味著，即使這些武將的忠誠度降至極低，甚至低於叛逃閾值，他們也無法觸發出奔事件。

這種封閉性缺陷導致了忠誠機制的「死區」（Dead Zone）。在 Q1–Q3 實驗中，忠誠／冷落機制在實際對局中從未觸發，部分原因即在於此。許多武將長期處於低忠誠狀態，但因地理位置限制而無法叛逃，使得忠誠度僅作為一個被動變數存在，無法對遊戲結果產生實質影響。此外，這種缺陷也影響了冷落機制（Neglect Mechanism）的有效性。君主若冷落後方武將，期望其因不滿而叛逃，但由於無法出奔，冷落行為僅導致忠誠度下降，卻無法產生預期的戰略後果。

此問題暴露了規則定義與地緣結構之間的脫節。未來的改進應重新定義出奔條件，例如允許「間接相鄰」或引入「戰略撤退」機制，使深處後方的武將也能在忠誠度極低時選擇出奔。或者，可以設計特殊的「內亂」事件，允許後方武將因忠誠度過低而引發城池內亂，從而間接影響遊戲進程。這些調整將使忠誠機制更具動態性，並能更真實地反映三國時期的人才流動與政治變遷。

## 12.4 評測流水線黑盒性

評測流水線（Evaluation Pipeline）是驗證 LLM 代理表現的關鍵工具，但目前的實作存在嚴重的黑盒性（Black-box Nature）問題。具體而言，`evaluate` 工具在整組實驗結束後才落地寫檔，導致長局模擬過程中無法即時觀察中間狀態。這種「中途不可見」的特性使得開發者難以診斷長局中的異常行為或策略演變。

在當前實作中，`slg.sim.evaluate` 模組在執行成對模擬時，將所有中間狀態與統計數據暫存於記憶體中，直至所有種子與回合完成後，才一次性輸出 Markdown 與 JSON 報告。這種設計雖然簡化了程式邏輯，但在長局模擬（如 40 回合）中造成了嚴重的可觀測性盲區。開發者無法在模擬進行中檢查 LLM 的決策趨勢、資源變化或忠誠度波動，只能等待實驗結束後進行事後分析。

這種黑盒性限制了迭代開發的效率。當實驗結果出現異常時，開發者難以快速定位問題根源。例如，若 LLM 在長局中突然改變策略或出現資源崩潰，開發者無法即時捕捉到這一轉折點，只能通過回溯大量日誌進行推測。此外，黑盒性也阻礙了即時調參與動態調整。開發者無法根據中間結果調整提示詞或參數，必須等待整組實驗結束後才能進行下一輪迭代。

未來的改進應引入即時寫檔與流式輸出機制。例如，可以將每個回合的狀態增量寫入日誌檔，或提供即時監控介面，顯示當前回合的關鍵指標（如兵力、資源、忠誠度）。這將大幅提高評測流水線的透明度與診斷效率，使開發者能夠在模擬進行中及時發現問題並進行調整。

## 12.5 資源爭用與決策反饋之粗糙性

LLM 代理在執行指令時，面臨資源爭用（Resource Contention）與決策反饋粗糙（Coarse-grained Feedback）的雙重挑戰。實驗數據顯示，約 20% 的指令因同城金幣爭用而被拒絕，這一高拒絕率嚴重影響了 LLM 的決策效率與遊戲表現。

在當前系統中，同一城池的多位武將可能同時發出需要金幣的指令（如 `develop_agri`、`recruit`），但城池的金幣預算有限。當多位武將的指令同時執行時，後發出的指令可能因金幣不足而被拒絕。這種「先到先得」的機制導致 LLM 無法預測指令執行的結果，必須在發出指令前自行估算金幣消耗。然而，LLM 難以精確計算多位武將的累積消耗，導致大量指令被拒。

此外，攻城歸因提示（Siege Attribution Hints）仍顯單薄。當 LLM 攻城失敗時，系統僅提供簡單的失敗原因（如「兵力不足」或「防禦過強」），缺乏詳細的歸因分析。例如，系統未告知 LLM 具體是哪個因素導致失敗（如兵力差距、防禦加成或隨機波動），使得 LLM 難以從失敗中學習並調整策略。這種粗糙的反饋機制限制了 LLM 的學習能力，使其難以在長局中優化攻城策略。

未來的改進應包括：在視圖中加入「各城可用金幣預算」的即時顯示，幫助 LLM 更準確地估算資源消耗；改進攻城歸因提示，提供詳細的失敗原因分解，如「兵力比低於 1.3」、「防禦加成過高」等，以幫助 LLM 理解失敗根源並調整策略。這些改進將降低資源爭用拒絕率，並提升 LLM 的決策品質。

## 本章重點
- `rest` 行動比例高達約 47%，反映出 LLM 在缺乏明確誘因時的決策惰性，需透過視圖設計與提示詞優化來增強主動性。
- 東南席位（`faction_3`）的邊角優勢導致自我對弈失衡，地緣結構對遊戲結果的影響超過策略能力，需進行地圖或初始條件平衡。
- 宛城與漢中武將因不與敵城相鄰，在規則定義下完全無法出奔，暴露了忠誠機制的封閉性缺陷，需重新定義出奔條件或引入內亂機制。
- `evaluate` 工具整組實驗結束後才寫檔，長局中途不可見，限制了即時診斷與迭代效率，需引入流式輸出與即時監控機制。
- 約 20% 指令因同城金幣爭用被拒，攻城歸因提示單薄，影響 LLM 決策效率與學習能力，需改進資源顯示與反饋機制。

## 習題
1. 若將 `rest` 行動的獎勵從 0 改為 -5（即每次休整扣除 5 點資源），預測 LLM 的 `rest` 比例會如何變化？這種變化是否一定能提升 LLM 的整體表現？請說明理由。
2. 設計一個實驗方案，用於分離地緣優勢與 LLM 策略能力對勝率的影响。請說明實驗變數、控制變數與預期結果。
3. 若允許宛城與漢中的武將在不與敵城相鄰時也能出奔，但出奔機率隨距離敵城的遠近而降低，請設計一個數學模型來計算出奔機率，並討論此模型對遊戲平衡的影響。
4. 在 `evaluate` 工具中引入即時寫檔機制，可能帶來哪些效能瓶頸？請提出兩種優化策略，並比較其優缺點。
5. 若將攻城歸因提示從「兵力不足」改為「兵力比 0.85（低於 1.3 閾值），防禦加成 +20%」，預測 LLM 的攻城成功率會如何變化？請設計一個實驗來驗證此預測。
6. 討論資源爭用問題中「先到先得」機制的公平性問題。若改為「按比例分配」金幣，對 LLM 的決策行為會產生何種影響？
