# 第 2 章：遊戲世界與規則

## 本章學習目標

- 理解三國式策略遊戲（SLG）中版圖拓撲、勢力分佈與初始資源配置的數學結構。
- 掌握回合制經濟循環中金錢與糧食的收入公式、隨機擾動機制及部隊維持成本。
- 分析武將政治力（politics）如何通過乘數影響農業、商業與防禦的開發效率。
- 解析攻城戰中的攻防強度計算、隨機變異係數以及兵力損耗與城池佔領的結算邏輯。
- 明確遊戲終局判定標準，理解以城池數與總兵力為基礎的字典序勝負裁定機制。

## 2.1 版圖與初始狀態

本遊戲引擎建立在一個確定性的初始狀態之上，該狀態由 `initial_state.py` 中的 `build_initial_state` 函式建構。版圖由三個勢力（faction）、九座城池（city）與四十二位武將（officer）組成。這種規模的設計旨在平衡計算複雜度與策略深度，使得大型語言模型（LLM）在有限的上下文視窗內能夠處理關鍵決策，同時保留足夠的變數空間以觀察長期的戰略演化。

三個勢力分別為：
1. **faction_1（曹操）**：初始佔有許昌（xuchang）、陳留（chenliu）與襄陽（xiangyang）。
2. **faction_2（劉備）**：初始佔有洛陽（luoyang）、宛城（wancheng）與漢中（hanzhong）。
3. **faction_3（孫權）**：初始佔有建業（jianye）、吳郡（wujun）與會稽（kuaiji）。

每座城池擁有獨立的狀態變數，包括農業（agriculture）、商業（commerce）、防禦（defense）、金錢（gold）、糧食（food）與兵力（troops）。以 faction_1 的首都許昌為例，其初始狀態設定為 `agriculture=550`, `commerce=550`, `defense=150`, `gold=1000`, `food=1000`, `troops=1400`。相較之下，邊境城市如陳留的資源較為貧瘠，`gold=600`, `troops=800`。這種資源分佈模擬了歷史上的經濟中心與邊境要塞的差異，迫使 AI 代理在決策時必須考慮資源調度的效率。

版圖的拓撲結構由 `adjacency` 字典定義，描述了城池之間的相鄰關係。這種鄰接關係決定了軍事行動的可行性：武將只能移動至相鄰的城池，攻城行動也僅能針對相鄰的敵對城池發起。根據 `initial_state.py` 中的定義，鄰接關係呈現出一個非完全圖的結構：
- 陳留僅與許昌相鄰。
- 許昌與陳留、洛陽、襄陽相鄰。
- 洛陽與許昌、襄陽、宛城相鄰。
- 襄陽與洛陽、許昌、建業相鄰。
- 建業與襄陽、吳郡相鄰。
- 宛城與洛陽、漢中相鄰。
- 漢中僅與宛城相鄰。
- 吳郡與建業、會稽相鄰。
- 會稽僅與吳郡相鄰。

## 2.2 經濟與維持循環

遊戲的每一回合開始時，引擎會執行 `apply_income` 函式，計算所有城池的經濟收入與維持成本。這一過程是確定性的，但引入了隨機擾動以模擬現實世界中的不確定性。

金錢收入主要來自商業發展。根據 `game.py` 中的定義，每座城池的金錢收入計算公式為：
`gold += int(commerce // GOLD_INCOME_DIV * rg)`
其中 `GOLD_INCOME_DIV` 是一個常數，設定為 3。`commerce` 是城池當前的商業值。`rg` 是一個隨機變數，由 `rng.uniform(0.8, 1.2)` 生成，代表 0.8 到 1.2 之間的均勻分佈隨機數。這意味著商業值每 3 點轉換為 1 點基礎金錢收入，並受到 20% 幅度的隨機波動影響。例如，若一座城池的 `commerce` 為 550，則基礎收入為 `550 // 3 = 183`，實際收入將介於 `183 * 0.8` 與 `183 * 1.2` 之間，並取整數部分。

糧食收入主要來自農業發展。計算公式為：
`food += int(agriculture // 4 * rf)`
其中 `rf` 同樣是由 `rng.uniform(0.8, 1.2)` 生成的隨機變數。農業值每 4 點轉換為 1 點基礎糧食收入。相較於金錢，糧食的轉換比率較低（除以 4 而非 3），這反映了農業生產週期較長且單位產出較低的特性。

收入計算完畢後，引擎會扣除部隊的維持成本。每座城池的部隊每回合消耗的糧食量為：
`food -= c.troops // 10`
這意味著每 10 名士兵每回合消耗 1 單位糧食。如果扣除維持成本後，城池的糧食儲備（food）小於 0，則會觸發斷糧機制。具體而言，糧食值會被強制設為 0，並且城池的兵力會發生 10% 的逃兵現象，計算公式為：
`troops = c.troops * 9 // 10`
這種機制模擬了糧荒對士氣的打擊，迫使 AI 代理必須在擴張與維持之間取得平衡。若過度擴張導致糧食供應鏈斷裂，兵力將不可避免地流失。

值得注意的是，`apply_income` 函式在 `sorted(state.cities)` 的順序下執行，這確保了在同一種子（seed）下，隨機數的抽取順序是固定的，從而保證了模擬的確定性與可重現性。

## 2.3 內政開發與武將能力

內政開發是提升城池長期產出能力的關鍵手段。引擎提供了三種開發行動：`develop_agri`（農業開發）、`develop_commerce`（商業開發）與 `develop_defense`（防禦開發）。每次開發行動需要消耗固定的金錢成本 `DEVELOP_COST`，其值為 50。

開發的增量並非固定值，而是由執行該行動的武將的政治力（politics）決定。`schema.py` 中定義了 `develop_gain` 函式：
`return base * (50 + politics) // 100`
其中 `base` 是該類型開發的基礎增量：
- 農業開發（`DEVELOP_AGRICULTURE_BASE`）：50
- 商業開發（`DEVELOP_COMMERCE_BASE`）：50
- 防禦開發（`DEVELOP_DEFENSE_BASE`）：25

這個公式表明，政治力直接影響開發效率。當 `politics` 為 0 時，增量為 `base * 50 // 100`，即基礎值的一半。隨著政治力的增加，增量線性增長。例如，若一位武將的 `politics` 為 50，則乘數為 `(50 + 50) // 100 = 1`，開發增量等於基礎值。若 `politics` 為 100，則乘數為 `(50 + 100) // 100 = 1.5`，開發增量為基礎值的 1.5 倍。

這種設計鼓勵 AI 代理將高政治力的武將分配至內政開發，而將高武力與統御的武將保留用於軍事行動。例如，faction_2 中的諸葛亮（zhuge_liang）擁有最高的政治力（98），若由其執行商業開發，增量將為 `50 * (50 + 98) // 100 = 74`，遠高於由政治力較低的武將執行的結果。這種屬性專化機制增加了遊戲的策略深度，要求代理在人力資源配置上做出精細的取捨。

此外，開發行動會立即更新城池的對應屬性（agriculture, commerce, 或 defense），並扣除 50 點金錢。如果城池的金錢不足 50，該行動將被驗證器拒絕，無法執行。這進一步強調了現金流管理的重要性。

## 2.4 軍事調度與攻城門檻

軍事行動的核心是攻城（siege）。為了防止 AI 代理使用過小的兵力進行無效的騷擾，引擎設定了出征的最小兵力限制 `MIN_SIEGE_TROOPS`，其值為 500。同時，出征城池必須保留至少 `SIEGE_MIN_GARRISON`（100）的兵力作為留守守軍。

攻城戰鬥的結果由攻方與守方的強度對比決定。`resolution.py` 中的 `_siege_strengths` 函式計算兩方的基礎強度：

**攻方強度（atk_base）：**
`atk_base = c * (0.5 + (officer.war + officer.leadership) / 200)`
其中 `c` 是出征兵力，`officer` 是執行攻城行動的武將。這個公式表明，攻方強度與兵力成正比，並受到武將武力（war）與統御（leadership）屬性的加成。當 `war + leadership` 為 0 時，加成係數為 0.5；當 `war + leadership` 為 200 時，加成係數為 1.5。

**守方強度（dfn_base）：**
`dfn_base = (def_troops * (1 + defender_city.defense / 200) * (0.5 + dq / 100))`
其中 `def_troops` 是城池的駐軍兵力，`defender_city.defense` 是城池的防禦值。`dq` 是守方城池內所有存活武將中，`(war + leadership) / 2` 的最大值。若城池內無存活武將，`dq` 設為預設值 `NO_OFFICER_DEFENSE_SKILL`，即 40。

這個公式體現了城防工事與守將能力的雙重防禦。防禦值每增加 200，守方強度增加 1 倍（即翻倍）。守將的綜合能力（`dq`）也線性影響守方強度。

在計算出基礎強度後，引擎會引入隨機擾動以模擬戰鬥的不確定性：
`atk = atk_base * rng.uniform(0.85, 1.15)`
`dfn = dfn_base * rng.uniform(0.85, 1.15)`

若 `atk > dfn`，攻方獲勝。城池的所有權將轉移至攻方勢力，且城池的兵力更新為攻方的倖存兵力。攻方的損耗計算公式為：
`loss = int(c * min(0.5, max(0.1, 0.4 * dfn / atk)))`
這意味著損耗比例介於 10% 到 50% 之間，具體取決於攻防比。若攻方壓倒性勝利（`atk` 遠大於 `dfn`），損耗趨近 10%；若攻方險勝，損耗趨近 50%。

若 `atk <= dfn`，攻方被擊退。攻方部隊返回出發城池，並承受較大的損耗：
`attacker_loss = int(c * min(0.8, max(0.3, 0.5 * dfn / atk)))`
守方也會承受一定的損耗：
`defender_loss = int(def_troops * min(0.3, 0.15 * atk / dfn))`

此外，若攻城成功且守方勢力失去最後一座城池（即滅國），該勢力內駐紮於該城的存活武將將轉投攻方勢力，其忠誠值被設為 60。若守方勢力仍保有其他城池，這些武將將撤退至該勢力擁有最小 ID 的其他城池。

## 2.5 勝負判定準則

遊戲的終局判定由 `compute_winner` 函式執行。當對局結束時（例如所有回合數已執行完畢，或僅剩一個勢力存活），引擎會計算每個勢力的得分，並依據字典序（lexicographical order）確定勝者。

每個勢力的得分是一個二元組：`(城池數, 總兵力)`。
- **城池數**：該勢力當前擁有的城池數量。
- **總兵力**：該勢力所有城池中兵力（troops）的總和。

勝者是被選出具有最大得分二元組的勢力。比較規則如下：
1. 首先比較城池數。城池數較多的勢力得分較高。
2. 若城池數相同，則比較總兵力。總兵力較多的勢力得分較高。
3. 若城池數與總兵力均相同，則視為平局，`compute_winner` 回傳 `None`。

這種判定標準強調了領土控制的重要性。在策略遊戲中，佔有城池意味著持續的資源收入與戰略據點，因此城池數被置於首要地位。總兵力作為次要指標，用於在領土規模相同的情況下區分軍事優勢。

例如，若 faction_1 擁有 4 座城池與 5000 兵力，faction_2 擁有 3 座城池與 8000 兵力，faction_3 擁有 2 座城池與 6000 兵力。則 faction_1 的得分為 (4, 5000)，faction_2 為 (3, 8000)，faction_3 為 (2, 6000)。由於 4 > 3 > 2，faction_1 獲勝，儘管其總兵力並非最高。

這種設計鼓勵 AI 代理在遊戲後期優先追求領土擴張，而非單純的兵力堆積。同時，它也為評測提供了客觀的量化指標，使得不同代理之間的表現可以通過勝率與最終得分進行比較。

## 本章重點

- 遊戲版圖由 3 個勢力、9 座城池與 42 位武將組成，鄰接關係決定了軍事行動的可行性與戰略樞紐（如襄陽）的重要性。
- 經濟循環中，金錢收入為 `commerce // 3`，糧食收入為 `agriculture // 4`，均帶有 U(0.8, 1.2) 的隨機擾動。
- 部隊維持成本為每 10 名士兵消耗 1 單位糧食，斷糧將導致 10% 的兵力逃失（`troops * 9 // 10`）。
- 內政開發增量由武將政治力決定，公式為 `base * (50 + politics) // 100`，強調了屬性專化在資源配置中的價值。
- 攻城需滿足最小兵力 `MIN_SIEGE_TROOPS`（500）與留守兵力限制，戰鬥結果由結合兵力、武將屬性、城防值與隨機擾動的強度公式決定。
- 勝負判定依 `(城池數, 總兵力)` 的字典序進行，優先考慮領土控制，其次考慮軍事實力。

## 習題

1. 假設一座城池的 `commerce` 為 1000，`agriculture` 為 800，`troops` 為 2000。若隨機擾動 `rg` 與 `rf` 均為 1.0，請計算該城池當回合的金錢淨收入與糧食淨收入（扣除維持成本後）。
2. 一位武將的 `politics` 為 80。若該武將執行 `develop_commerce` 行動，其商業值的增量是多少？若另一位武將的 `politics` 為 20，其增量又是多少？兩者相差幾點？
3. 攻方以 1000 兵力攻城，執行武將的 `war + leadership` 為 150。守方城池駐軍 800 兵力，`defense` 為 100，城內最佳守將的 `(war + leadership) / 2` 為 60。假設隨機擾動均為 1.0，請計算攻方與守方的基礎強度（atk_base 與 dfn_base），並判斷攻方是否可能獲勝（忽略隨機擾動的最終結果，僅比較基礎強度）。
4. 若遊戲結束時，faction_1 擁有 5 座城池與 10000 兵力，faction_2 擁有 5 座城池與 12000 兵力，faction_3 擁有 6 座城池與 8000 兵力。請根據勝負判定準則，指出哪位勢力獲勝。
5. 考慮斷糧機制。若一座城池在扣除維持成本前糧食為 50，部隊為 1000。請計算扣除維持成本後的糧食值與部隊值。若糧食為 0，部隊值又會如何變化？
6. 在 `initial_state.py` 中，faction_3 的建業（jianye）與吳郡（wujun）相鄰。若 faction_3 的武將從建業移動至吳郡，該行動是否合法？若 faction_3 的武將試圖從建業直接移動至宛城（wancheng），該行動是否合法？請根據鄰接關係說明理由。
