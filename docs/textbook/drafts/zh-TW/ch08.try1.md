# 第 8 章：評測方法

## 本章學習目標

1. 理解「同座位、同種子成對比對」設計在消除初始地圖不對稱與隨機變因上的科學價值。
2. 掌握規則 AI 基準線（Rule-based baseline）的標定流程與對稱性驗證方法。
3. 區分 `default` 標準情境與 `advantage` 進攻優勢情境的設計目標與實驗意涵。
4. 熟悉 `max_calls` 呼叫預算與斷路器機制（Circuit Breaker）在防止無窮迴圈與 Token 浪費中的作用。
5. 學會解讀多維度診斷指標（diagnostics），包括勝率差、兵力差、接受率、攻城勝率與事件損耗曲線。

## 8.1 評測哲學：同座位、同種子成對比對

在三國 SLG 遊戲環境中，各勢力的初始條件存在高度結構性差異。以第 2 章所述的遊戲世界為例，`faction_1`（曹操）在地理位置、初始城池數量與將領素質上往往優於 `faction_2`（劉備）或 `faction_3`。若直接比較不同席位（seat）的 LLM 代理勝率，將無法區分「LLM 決策品質」與「初始資源優勢」兩者對結果的影響。例如，若 `faction_1` 的 LLM 勝率為 80%，而 `faction_2` 的 LLM 勝率為 20%，這可能僅反映 `faction_1` 的先天優勢，而非 LLM 在兩個席位上的決策能力差異。

因此，本章採用**同座位同種子成對比較**（Paired Comparison）作為核心評測哲學。具體而言，在相同的隨機種子（random seed）下，系統會執行兩場對局：
1. **基準局（Baseline Game）**：所有勢力（包括目標席位）均由規則 AI 代理（Rule-based agent）掌管。
2. **實驗局（Experiment Game）**：僅目標席位（預設為 `faction_2`）由 LLM 代理掌管，其餘勢力維持與基準局完全相同的規則 AI 代理。

這種設計確保了兩場對局在初始地圖、隨機事件序列（如資源刷新、天氣變化）與敵方行為上完全一致。透過比較同一席位在 LLM 與規則 AI 控制下的最終狀態差異，可以精確量化 LLM 相較於規則基準線的淨增益或劣勢。此方法嚴格消除了初始地圖不對稱帶來的勝率偏差，使得實驗結果具有科學可比性。

此外，隨機種子的控制對於消除模擬中的隨機變因至關重要。SLG 模擬包含大量隨機事件（如將領忠誠度波動、攻城損耗隨機項），單一種子的結果可能受偶發事件影響而缺乏代表性。因此，評測需跨越多個種子（如 0-9 或 0-39）進行統計聚合，以確保結論的穩健性。

## 8.2 規則 AI 基準線標定

在引入 LLM 代理之前，必須建立一個可靠的規則 AI 基準線，用以作為對照組。規則 AI 代理（`RuleBasedAgent`）依據預設的策略風格（如 `balanced`）執行決策，其行為確定性高、可重複性強，適合用作基準。

基準線的標定需驗證其對稱性與平衡性。在理想的對稱情境下，若所有勢力均由規則 AI 掌管，且初始條件完全對稱，則各勢力的勝率應趨近於相等。然而，由於遊戲地圖的結構性差異（如 `faction_1` 的資源優勢），完全對稱難以實現。因此，標定工作著重於確認規則 AI 在不同席位上的表現是否符合預期，並記錄其作為基準的穩定性。

基準線標定的關鍵在於確保規則 AI 的行為一致且可預測。透過固定種子與情境，研究者可以精確計算 LLM 代理在每個種子上的勝率差異（win_rate_delta），並進行統計顯著性檢驗。若樣本數足夠大（如 40 種子以上），則可透過 t 檢定或 bootstrap 方法評估 LLM 增益的統計顯著性。

## 8.3 情境設計：default 標準情境 vs advantage 進攻優勢情境

為了全面評估 LLM 代理在不同戰略環境下的表現，評測框架支援多種初始情境（scenario）。主要情境包括 `default` 標準情境與 `advantage` 進攻優勢情境。

**`default` 標準情境**：
此情境使用預設的初始狀態，各勢力的兵力、城池與資源分配遵循遊戲標準規則。此情境用於評估 LLM 在常態下的決策能力，包括資源管理、將領委派與防禦策略。在 `default` 情境下，LLM 面臨的挑戰主要是如何在資源有限的條件下維持勢力平衡並尋求突破。

**`advantage` 進攻優勢情境**：
此情境專門設計用於測試 LLM 的進攻判斷能力。在 `advantage` 情境中，目標席位（如 `faction_2`）被賦予顯著的兵力優勢，例如初始兵力遠高於其他勢力。此情境的設計目標是檢驗 LLM 是否能夠識別並利用這種優勢，主動發起進攻以擴大戰果，而非僅採取防禦姿態。

在素材的實驗結果中，Q2 實驗（`faction_2` 在 `advantage` 情境下）顯示，LLM 在兵力優勢下進行了 10 次攻城，成功 7 次，而在 7/10 個種子中多拿一城。相比之下，規則 AI 在相同情境下進行了 7 次攻城，但全數失敗。這表明 LLM 在有利局面下具備更佳的進攻判斷能力，能夠有效利用兵力優勢轉化為領土擴張。

然而，在 `default` 情境下，LLM 的表現可能較為保守。例如，在 Q1 實驗中，LLM 的攻城嘗試較少且成功率低，這可能因為 LLM 在缺乏明確優勢時更傾向於風險規避。透過對比 `default` 與 `advantage` 情境的結果，研究者可以深入理解 LLM 的戰略傾向及其在不同風險環境下的適應能力。

## 8.4 預算與保護機制：max_calls 呼叫上限防範無窮迴圈與 Token 浪費

LLM 代理的決策過程依賴於多次 API 呼叫，這可能導致高昂的 Token 成本與計算延遲。此外，若 LLM 陷入無窮迴圈（如反覆生成相同錯誤指令）或後端連線不穩定，評測流程可能無限期延遲或耗盡資源。因此，評測框架內建了嚴格的預算與保護機制。

**呼叫預算（Call Budget）**：
透過 `--max-calls` 參數設定全局累計呼叫上限（如 130 次）。`CallBudget` 類別會追蹤每次 LLM 呼叫，當累計呼叫數達到上限時，系統將優雅終止剩餘種子並輸出部分統計。這確保了評測不會因單一種子的異常行為而耗盡整體預算。

**斷路器機制（Circuit Breaker）**：
由 `--max-consecutive-errors` 控制（預設 3 次）。若後端連續發生連線異常或 HTTP 錯誤達到上限，`CircuitBreakerCompleter` 會自動熔斷並即時中止評測流程。這避免了在後端故障時無謂消耗配額，並透過 `aborted` 標誌與 `abort_reason` 記錄中止原因，便於後續除錯。

**共享計數器（SharedCallCounter）**：
在批次評測（batch evaluation）中，多個席位與情境可能並行執行。`SharedCallCounter` 提供線程安全的全局計數機制，確保所有並行任務共享同一個呼叫預算。當任一任務觸發預算上限時，所有任務將停止，防止總呼叫數超出預期。

這些保護機制不僅提升了評測的穩定性與成本可控性，也確保了實驗結果的可重複性。例如，在素材的 Q1 實驗中，`max_calls` 設定為 203 次，實際使用 203 次，未觸發提前終止，顯示預算設定合理。若預算過低，可能导致評測中途中止，影響統計顯著性；若預算過高，則可能浪費資源。因此，預算設定需根據模型效率與實驗規模進行調整。

## 8.5 多維度診斷指標：勝率差、兵力差、接受率、攻城勝率與事件損耗曲線

僅依靠勝率（win rate）無法全面評估 LLM 代理的策略表現。評測框架提供多維度診斷指標（diagnostics），以深入分析 LLM 的決策品質與潛在問題。

**勝率差（win_rate_delta）**：
計算實驗組勝率與基準線勝率的差異。例如，若基準勝率為 0.0%，實驗勝率為 16.7%，則勝率差為 +16.7%。此指標直接反映 LLM 對最終勝負的影響。

**兵力差（mean_troops_delta）**：
計算實驗組與基準線最終兵力的平均差異。正值表示 LLM 保有更多兵力，負值表示兵力損失較大。例如，在素材的初版評測中，平均兵力差為 -3830.3，顯示 LLM 在攻城過程中遭受重大損失。

**指令接受率（orders_accept_rate）**：
衡量 LLM 生成的指令被引擎接受的比率。低接受率通常表示 LLM 生成的指令存在格式錯誤或邏輯不合規問題。例如，初版評測中接受率為 84.1%，主要因參數格式錯誤（如遺漏 `to` 參數）。在參數格式修正後，接受率提升至 94.3%，顯示提示詞優化對指令品質的顯著改善。

**攻城勝率（siege outcomes）**：
記錄攻城嘗試次數、成功攻克次數與擊退次數。此指標直接反映 LLM 的進攻判斷能力。例如，在 Q2 實驗中，LLM 攻城 10 次成功 7 次，而規則 AI 攻城 7 次成功 0 次，顯示 LLM 在優勢情境下具備更佳的進攻策略。

**事件損耗曲線（officer_loss_curve）**：
追蹤每回合末目標席位的存活武將數量。此曲線可揭示將領流失的時間點與原因（如出奔、戰死）。例如，在忠誠機制重調實驗中，`Stubborn` 策略的出奔種子比例為 100%，而 `Rotator` 策略為 0%，顯示不同委派策略對將領忠誠度的影響。

此外，診斷報告還包含**被拒指令原因前 3 名**（rejection_reasons）與**點名與委任平均**（named_per_turn），幫助研究者識別 LLM 的具體弱點（如資源爭用、參數格式錯誤）並進行針對性優化。

## 本章重點

1. **同座位同種子成對比對**是消除初始地圖不對稱與隨機變因的核心方法，確保 LLM 增益的科學可比性。
2. **規則 AI 基準線**需經過對稱性驗證，其勝率分布可能反映遊戲設計的座位不平衡，而非決策品質差異。
3. **`default` 與 `advantage` 情境**分別用於評估常態決策與進攻判斷能力，LLM 在優勢情境下表現更佳。
4. **`max_calls` 與斷路器機制**有效防止無窮迴圈與 Token 浪費，確保評測的穩定性與成本可控。
5. **多維度診斷指標**（勝率差、兵力差、接受率、攻城勝率、事件損耗曲線）提供深入洞察，幫助識別 LLM 的決策弱點與優化方向。
6. **統計顯著性**需依賴足夠大的種子數（如 20 個以上），小樣本結果易受偶發事件影響，不具統計顯著性。
7. **參數格式錯誤**是 LLM 指令被拒的主要原因之一，透過提示詞示範與解析器優化可顯著提升接受率。
8. **忠誠與冷落機制**的驗證需結合長局實驗，短局中機制可能未觸發，無法充分評估其影響。

## 習題

1. 解釋為何直接比較不同席位（如 `faction_1` 與 `faction_2`）的 LLM 勝率不具科學意義，並說明「同座位同種子成對比對」如何解決此問題。
2. 假設在某次評測中，基準線勝率為 20%，實驗組勝率為 30%，種子數為 10。請計算勝率差，並討論在如此小樣本下，該差異是否可能僅由隨機變因造成。
3. 描述 `max_calls` 參數與斷路器機制（Circuit Breaker）在評測流程中的作用。若後端連續發生 3 次連線異常，系統將如何回應？
4. 在 `advantage` 情境中，LLM 攻城 10 次成功 7 次，而規則 AI 攻城 7 次成功 0 次。請分析此結果可能反映的 LLM 戰略特徵，並討論其局限性。
5. 若某次評測的指令接受率為 80%，且被拒指令原因前 3 名為「參數格式錯誤」、「兵力超出範圍」與「資源不足」，請提出兩種可能的優化策略以提升接受率。
6. 解釋「事件損耗曲線」（officer_loss_curve）的意義，並說明如何透過此曲線診斷將領忠誠機制的有效性。
